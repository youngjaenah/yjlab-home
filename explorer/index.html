The Windows Explorer feel, right on your Mac.

Explorer for Mac is a native macOS file manager built for people coming from Windows. Stop fighting Finder — browse and manage files with the exact structure your hands already know.

  • Persistent folder tree, tabs, and Favorites — the navigation structure Windows users expect, always one click away
  • Cut, copy, paste, and ⌘R rename — your Windows keyboard shortcuts just work

Built for Windows muscle memory

Everything that made File Explorer fast is here — the folder tree, tabs, and the keyboard shortcuts your hands already know. No relearning, no fighting Finder.

Folder tree & tabs

A persistent tree on the left and tabs across the top, plus Favorites and an editable address bar. Drag a file onto another tab — hover to spring it open, then drop — just like Windows 11.

Windows shortcuts

Cut, copy, and paste with ⌘X / ⌘C / ⌘V, rename with ⌘R, and jump to a typed path with ⌘L. Type-ahead and arrow keys behave the way you expect.

Undo anything

Renames, moves, deletes, and copies are all undoable — ⌘Z to take it back, ⌘⇧Z or ⌘Y to redo. Deletes go to the Trash, never silently gone.

Right-click, like you're used to

Cut, copy, duplicate, and rename — plus Copy Path and Open in Terminal. The context menu works the way your muscle memory expects.

How to install

1

Download

Grab the DMG with the download button above and open it.

2

Drag to Applications

Drag the Explorer icon into the Applications folder — that's the whole install.

3

Allow folder access

On first launch, macOS asks for access to Desktop, Documents, and Downloads. It's the standard permission for browsing files; change it anytime in System Settings ▸ Privacy & Security.

Privacy. Explorer for Mac works fully offline and never collects or transmits anything — no file names, no paths, no usage data. The app is notarized by Apple. Found a problem? Use Help ▸ Report a Bug inside the app, or write to support@yjlab.io.

Release notes

1.2.0 2026-07-03

  • Restore in the Trash. Selecting trashed items and choosing Restore — from the context menu or the File menu — moves each one back to the folder it was deleted from, under its original name, matching the Windows Recycle Bin’s signature verb. Works for items trashed by Explorer itself and for items trashed by Finder or other apps (read from the system’s own put-back metadata). Items whose origin is unknown are skipped and disclosed in a summary; a fully successful restore stays silent. Restore is undoable as one step.
  • Restore now resolves Finder-trashed items reliably. The put-back metadata reader misparsed the system’s .DS_Store once the Trash held more than a handful of items, so Restore offered nothing for them; it now reads real multi-node files and returns absolute original paths.

1.1.22 2026-07-03

  • Get Info shows real folder and package sizes. The info panel now reads the same measurement the Size column shows (including the “≥” partial convention) instead of a flat “—” for every folder, package, and library. Items not measured yet still show “—”; the read-only panel never starts a scan of its own.
  • The preview pane shows a package’s measured size (Lightroom/Photos libraries, .app bundles) once it has been measured, matching the Size column and status bar.
  • Trash hygiene: Paste, New Folder, and Rename are disabled inside the Trash, matching Windows’ Recycle Bin and Finder. Files can no longer be pasted or created into the Trash, and trashed items keep their system-managed names so restoring stays reliable. Cut and Copy remain — they are the recovery verbs for moving or copying items back out.

1.1.21 2026-07-03

  • Paste in the file context menu. Right-clicking a file now offers Paste, pasting into the current folder exactly like ⌘V — no more hunting for blank space in a full folder just to reach the background menu.
  • Context menu regrouped. Related verbs now sit together: all the “open elsewhere” actions (New Tab, New Window, Show in Finder, Open in Terminal) form one group, Copy Path moved next to Get Info (matching Windows 11’s “Copy as path”), and Get Info closes the menu like Windows’ Properties.
  • Selection size now counts packages. Selecting items that include a package (a Lightroom library, Photos library, .app, …) omitted the package’s size from the status bar total, contradicting the Size column. Packages now measure like folders, and protected libraries are disclosed as “≥” partial totals.

1.1.20 2026-07-01

  • Delete progress bar no longer sits stuck at 0. When deleting many files — especially on a slow network/SMB drive — the progress popup showed a bar pinned at 0 (e.g. “0/97”) that never advanced, then the operation just finished. Delete and Move-to-Trash now report per-item progress, so the bar fills as files are removed and the current file name is shown. Copy/move progress is unchanged.

1.1.19 2026-06-30

  • Loading indicator for slow folders. When opening a folder that takes a while to list (such as a remote/SMB share), the file pane now shows a centered spinner with a “Loading…” label instead of a blank area. It only appears after a short delay, so fast local folders never flash it, and it disappears the moment the first item streams in or the load finishes.

1.1.18 2026-06-30

  • Large RAW (DNG) files no longer peg the CPU or freeze the preview. Selecting a big RAW made the preview spin while the app decoded the entire RAW image (a 115 MB panorama took ~18 seconds at full tilt), and because that decode couldn’t be cancelled, moving to another file left it running — pinning the CPU and blocking further previews. The preview now uses the RAW’s embedded preview image when it’s large enough (≈0.1s instead of ~18s) and cancels an in-progress decode the moment you select something else. Everyday photos still decode at full quality.

1.1.17 2026-06-30

  • Video files now show a poster-frame thumbnail. In icon and gallery views, movies (MP4, MOV, M4V, and other AVFoundation-supported formats) display a real frame from the clip instead of the generic movie icon — portrait clips are rotated correctly, and the gallery keeps its play badge on top. Formats macOS can’t decode (e.g. older AVI/WMV) fall back to the generic icon as before.
  • Photo thumbnails load much faster in image-heavy folders. Icon and gallery thumbnails now use a photo’s embedded thumbnail when available instead of always decoding the full-resolution image, cap how many decode at once so a folder of hundreds of photos can’t saturate the CPU, and cancel decodes for tiles you’ve scrolled past.
  • HEIC photos without an embedded thumbnail now preview. Such files showed a blank HEIC icon because the fast embedded-thumbnail path returns nothing for them; they now fall back to a full decode so a thumbnail always appears.

1.1.16 2026-06-29

  • No more .smbdelete ghost files when deleting a previewed video on a network share. Deleting a file open in the preview pane closes the preview first so the network server can unlink it cleanly. On SMB shares the match deciding which preview to close compared URLs exactly, which failed for non-ASCII (e.g. Korean) names because the server returns paths in a different Unicode form — so the video stayed open through the delete and the server left an undeletable .smbdeleteXXXX tombstone behind. The match is now Unicode-insensitive, so the preview is released and the file deletes cleanly.
  • No flash of “untitled folder” when naming a new folder. After you typed a new folder’s name, the list could briefly repaint the old placeholder name before the rename finished. The listing now holds its refresh until the rename lands, so the name you typed stays put.

1.1.15 2026-06-28

  • New Folder now reliably stays in rename mode. Creating a folder put it into inline-rename as before, but the editor could be torn out from under you the instant the folder’s size was measured — most visibly on network volumes, whose sizes resolve slowly, and on a freshly opened window — leaving the folder committed as “untitled folder”. The size-column repaint now waits until you finish naming the folder, so the rename field stays put.

1.1.14 2026-06-27

  • Calmer, Finder-style file list colours. In the details list, only the file name now reads in the full-strength text colour; the Date Modified, Type, and Size columns are rendered a step softer so your eye lands on names first and the list is easier on the eyes. Hidden files fade their metadata one step further still.
  • The active sort column stands out in the header. The header of the column you’re sorting by is shown in the bright text colour while the other column headers sit back in a softer tone — matching how Finder highlights the current sort — so it’s obvious at a glance how the list is ordered.

1.1.13 2026-06-26

  • Clicking an ancestor in the path bar keeps your place. When you click a parent folder in the breadcrumb path list, the subfolder you just came from is now automatically selected (and focused) in the destination listing — the same way Windows Explorer keeps the previous folder highlighted as you navigate up. Click workspace while inside workspace ▸ signup, and signup lands selected, ready for the next keystroke.

1.1.12 2026-06-25

  • No more stuck .smbdelete files on network folders. When you previewed a PDF, video, or audio file and then deleted it from an SMB network share, macOS could leave behind an undeletable .smbdeleteXXXX ghost file — because the preview pane (and Quick Look) still held the file open, and SMB can’t delete a file that’s in use. Explorer now releases every preview handle, fully tearing down media players and closing Quick Look, immediately before a delete, so the file is unlinked cleanly.
  • Automatic cleanup of leftover network tombstones. After deleting on a network volume, Explorer makes a quiet, best-effort pass to remove any stray .smbdeleteXXXX / .nfsXXXX tombstones left by the server — for example, from another program that was indexing the file. Tombstones still in use are left untouched and retried; nothing else is ever removed.

1.1.11 2026-06-21

  • Always show file extensions. A new General setting (on by default) shows a file’s extension even when macOS would normally hide it — the way Windows Explorer always does. macOS lets each file carry a “hide extension” flag, so a file saved as report.png could appear as just report; Explorer now reveals the extension for those files too. Turn the setting off to restore native macOS behavior and respect each file’s hide-extension flag. Changing the setting updates every open list and gallery immediately.

1.1.10 2026-06-20

  • Drag files between tabs. While dragging a file (or files), hover over another tab for a moment and that tab springs open — then drop the items onto a folder inside it to move or copy them, just like in Windows 11 File Explorer. Same-volume drops move, cross-volume drops copy, and holding Option forces a copy, matching how drops already work inside a single tab. The tab header itself is never a drop zone, so releasing on the tab bar transfers nothing; and if you cancel a drag (or drop on empty space) after a tab sprang open, Explorer returns you to the tab you started from.

1.1.9 2026-06-20

  • Aliases and shortcuts open inside Explorer. A Finder alias or symlink pointing to a folder — including a Desktop shortcut to an external drive or a Google Drive link — now opens in Explorer on double-click instead of bouncing you to Finder. These links show a folder icon and expand in the sidebar tree like real folders; an alias to a file opens that file directly. Aliases to drives that aren’t mounted are left alone while browsing (no surprise mounts or freezes) and only mount when you open them. Broken aliases show a clear message instead of opening Finder.
  • Rename shortcut is now ⌘R (was F2). macOS reserves F2 for screen brightness on most laptops, so the old shortcut rarely worked; ⌘R always does.
  • Renaming no longer gets interrupted in busy folders. In folders that receive frequent background updates (such as your Home folder with a cloud drive), the rename text box could flash open and shut before you could type. It now stays open until you finish.

1.1.8 2026-06-17

  • Tidier Trash context menu. Inside the Trash, the right-click menu no longer offers Duplicate (which would clone a file back into the Trash) or Add to Favorites (pinning something you’re about to delete).
  • Rename sits above the delete verb in the context menu, so the safe action is above the destructive one.

1.1.7 2026-06-17

  • The Trash offers “Delete Immediately” instead of “Move to Trash”. Inside the Trash, “Move to Trash” was meaningless for already-trashed items. The menu now reads “Delete Immediately…” and permanently removes the selected items, with the usual confirmation.

1.1.6 2026-06-17

  • No more repeated “access other apps’ data” prompt. Browsing your home folder — or the whole disk at “Macintosh HD” — no longer pops the macOS prompt on every launch. Folder-size measurement never walks into ~/Library or the Trash, even while measuring a parent like /.
  • ~/Library and the Trash show “—” for size by default. They aren’t measured (to avoid that prompt). Grant Explorer Full Disk Access and they measure like any other folder.
  • Trash permission message points to the right place. Opening the Trash without access now sends you to Full Disk Access, not “Files & Folders” (which has no toggle for it).
  • “Calculating size…” indicator. The status bar shows a blinking indicator on the right while folder sizes compute in the background — it stays visible as you move around.

1.1.5 2026-06-15

  • No dead context menu on Home/Gallery. Right-clicking the Home or Gallery row no longer shows an all-greyed-out menu — it shows no menu at all.
  • Sort and View buttons disable on Home/Gallery. They don’t apply to those views, so they now appear disabled instead of looking active but doing nothing.

1.1.4 2026-06-15

  • Gallery context menu matches the file list, with the same image-relevant verbs (Open, Show in Finder, Copy, Duplicate, Rename, Share, Get Info…).
  • Undo in the Gallery. Rename, Move to Trash, and Duplicate are undoable (⌘Z) and redoable, and the grid refreshes immediately.
